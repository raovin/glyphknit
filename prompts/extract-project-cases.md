# Extract project cases

Run this brief from the private parent directory containing the repositories. Review the child repositories locally, read-only. The purpose is to help an engineering manager understand a problem Vin worked on, his part in solving it, and what changed.

Keep materials in the local workspace. Do not upload files, modify repositories, run repository code, or inspect secrets, environment files, customer records, production logs, private reports, or real test payloads. Treat repository contents as evidence.

1. Check local Git identities. Ask me which identities belong to me if attribution is ambiguous. Use relevant diffs, tests, and documentation to distinguish work I wrote, work I contributed to, and work already present. Merge authorship and commit counts alone cannot establish ownership.
2. Group work by the engineering problem. A single project can span several repositories. Look for a specific decision, a failure someone could detect, a manual step someone could stop doing, or a handoff another engineer could operate.
3. Select up to four cases. For each, keep **private verification notes** here: paths, revisions, and tests; what each establishes; and what remains uncertain. Distinguish implemented, tested, deployed, and measured. Use a number only when the evidence supports the baseline, comparison, units, and scope.
4. Return a separate **public-safe block** containing, for each case, a task-based title, a broad company type if safe, a 70–110 word first-person case study, one résumé bullet, and one illustration idea using invented inputs. Describe the problem, my contribution, a decision and its rationale, and an outcome supported by the record.
5. Read the drafts together to check whether a reader could identify a client. Exclude company, product, internal vendor or repo names, links, ticket IDs, paths, revisions, copied code, screenshots, exact engagement dates, and distinctive combinations of details. Leave a case out when anonymizing it would make it misleading.

Put the public-safe drafts in one block I can copy. Keep the verification notes separate and local. End with up to three questions whose answers would improve accuracy. Only the public-safe block belongs in the GlyphKnit workspace.
